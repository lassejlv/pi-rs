# Test map: TypeScript tests vs Rust tests

Every `packages/coding-agent/test/**/*.test.ts` file (including `test/suite/**`) with the Rust tests that cover it. Generated from three sources and then reviewed by hand: header comments in Rust test files that name the TS file they port, `#NNNN` issue references for `suite/regressions`, and Rust test names that match a TS `it()` title. Rust tests often group several TS cases into one test, so the Rust count can be lower than the TS case count even when every case is checked.

Statuses:

- **COVERED**: the cases are ported (possibly grouped).
- **PARTIAL**: some cases are ported; the note says what is missing or why.
- **MISSING**: no Rust counterpart yet.
- **NOT PORTABLE**: tests a Node/Bun/TS-only mechanism; the note gives the reason.
- **IN PROGRESS (session agent)**, **IN PROGRESS (extension agent)**: owned by the agent porting that area.
- **INTERACTIVE (later audit)**: interactive-mode, component and selector tests, left for the UI audit.
- **E2E (needs credentials)** (other packages): live-provider tests without an offline counterpart.
- **UNVERIFIED** (other packages): no Rust test names the TS file; the listed provider tests are the likely counterparts and need a case-by-case check.

Summary for `packages/coding-agent/test` (308 files): COVERED: 228, PARTIAL: 36, INTERACTIVE (later audit): 18, IN PROGRESS (extension agent): 14, NOT PORTABLE: 12.

The agent-session suites (`agent-session-*`, `suite/agent-session-*`, `sdk-*` and most `suite/regressions`) were ported by the session-engine agent in `tests/agent_session/`; rows show COVERED where that work has landed. Example-extension and loader tests belong to the extension agent.

Run a ported test with `cargo test -p pi-coding-agent --test <file stem> <name>` (integration tests in `tests/`) or `cargo test -p pi-coding-agent --lib <module path>` (unit tests in `src/`).
